# BSHUSHU FLIGHT CLUB — паспорт проекта

Актуализировано: 21 октября 2026. Этот файл — рабочая документация для продолжения разработки в новых чатах. Перед изменениями сверяйте код и конфигурацию с действующими GitHub/Supabase: документация может устареть.

## Ссылки и инфраструктура
- Игра (Vercel): https://bshushu-flight-club.vercel.app/
- Репозиторий: https://github.com/Stanislav-naum/bshushu-flight-club
- Основной игровой код: `index.html` (canvas + HTML/CSS/JS в одном файле).
- Страница персонального подарка: `prize.html`, адрес `https://bshushu-flight-club.vercel.app/prize.html?code=...`.
- Supabase: проект `vtllofdosyrfqdqrjwwg`, API URL `https://vtllofdosyrfqdqrjwwg.supabase.co`.
- Telegram: бот BSHUSHU Flight Club, команды `/start <flight UUID>` и `/prize`.
- Не записывать в репозиторий Telegram-токены, service role key, PIN-коды, персональные ссылки победителей и телефоны.

## Игровая механика
- Самолёт, четыре страны в порядке **Греция → Франция → Испания → Турция**.
- Три жизни, бонусные мили, препятствия-чайки и грозовые тучи с молниями.
- Бонусы: еда соответствующей страны и бутылка вина (временное изменение управления); иногда дополнительная жизнь.
- Первые 5 секунд безопасного полёта с обратным отсчётом.
- Обучение после заставки, мобильная адаптация, смена фонов и короткие истории о странах.
- Зачётные полёты и рейтинг; призы для ТОП-3: **1 — пицца, 2 — десерт, 3 — напиток**. Проверять точные ограничения попыток и формулу рейтинга в коде/SQL перед изменениями.
- Важно: сервер проверяет игровые результаты; не менять физику полёта, генерацию препятствий, scoring, seed/replay без согласованной правки серверной валидации.

## Призы: текущий рабочий сценарий
1. По итогам недели определяются призёры; уведомление Telegram содержит **персональную ссылку** на `prize.html?code=...`.
2. Страница обращается к Edge Function `bshushu-prize` для просмотра подарка и его статуса.
3. Сотрудник вводит **трёхзначный код соответствующей недели**; значения хранятся в базе, не в клиентском HTML.
4. При корректном коде подарок помечается погашенным; повторное погашение отклоняется.
5. Предусмотрено ограничение ошибочных попыток PIN (5 в час для конкретного подарка).
6. 21.10.2026 был проверен реальный сценарий погашения пиццы: статус в БД `redeemed_at` установлен. Не запускать повторные тестовые отправки реальным победителям.

**Внимание:** старый RPC `public.bsh_flight_redeem(text)` существует отдельно; перед расширением функционала нужно провести аудит прав EXECUTE и обходных путей погашения. Не считать PIN единственным гарантированным барьером до такого аудита.

## Графика и последнее решение
- Пользователь попросил более мультяшную чайку; новая процедурная версия оказалась неудачной.
- **Решение пользователя: вернуть старую чайку.**
- Старая иллюстрированная 24-кадровая анимация восстановлена в `index.html` коммитом `0bda1eb26463c8e5b783c261a1c0557b27dbe5ec`.
- Не возвращать процедурную мультяшную чайку без нового прямого запроса.
- Облака, молнии, анимация фона и другие элементы сохранять при точечных правках.

## Правила дальнейшей работы
1. Перед изменением читать актуальный `index.html` и связанные Edge Functions, не работать с устаревшей копией.
2. Менять **только согласованный элемент**, не переписывать игру целиком.
3. Сохранять мобильную производительность, текущую механику, начисление миль и серверную валидацию.
4. Каждое изменение фиксировать отдельным понятным GitHub-коммитом; при необходимости указывать SHA для отката.
5. Проверять публикацию Vercel и поведение на телефоне; коммит GitHub сам по себе не доказывает успешный деплой.
6. При изменении уведомлений не отправлять повторные призы реальным игрокам.
7. Не публиковать персональные коды, секреты, номера телефонов и данные игроков.
8. После заметных изменений обновлять этот файл и раздел истории.

- **Безопасность:** Supabase advisory сообщает, что RLS отключён на `bsh_flight_private.prize_pin_attempts`. Таблица находится в private-схеме, но необходимо проверить grants и exposure; решение о включении RLS и политиках принимать после аудита доступа. Не применять изменения автоматически.
- Проверить, что legacy RPC погашения недоступен анонимным клиентам без PIN.
- После очередного деплоя проверить CORS, получение статуса подарка и повторное погашение.
- Периодически сверять расписание weekly winners и Telegram webhook.
